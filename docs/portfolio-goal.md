# 作品集目标定位

## 一句话定位

**产品体验 / UXUI 设计师，擅长把用户问题转化为清晰界面，并推进到可体验、可落地的产品。**

## 协作目标

这份文档是后续整理作品集、筛选项目、组织案例和调整网站内容的核心依据。

主要任务不是简单罗列已有作品，而是帮助我完成一个更适合求职的作品集：始终以“产品体验 / UXUI 设计师”的目标为导向，判断每个项目、页面、文案和视觉表达是否服务于这个方向。

如果素材、职责、项目价值或展示方式不够清楚，可以主动向我提问。提问应围绕作品集目标展开，例如：这个项目里我具体负责什么、是否有完整流程、是否能展示交互判断、是否有可体验结果、是否会让招聘方误读为运营 / 平面 / 营销设计方向。

后续协作中，需要持续提醒我做取舍：优先保留能证明产品理解、用户路径、交互逻辑、复杂界面和落地能力的内容；弱化或删除只体现视觉执行、物料支持、活动运营或单纯好看的内容。

## 主线

- 主定位：产品体验型 + 产品落地型设计师
- 重点能力：产品理解、用户路径、交互逻辑、界面落地
- 作品集气质：专业、稳定、清楚、可信
- 避免方向：运营设计、平面设计、营销物料、纯视觉执行

## 作品集取舍原则

每个项目优先证明：

- 我理解了什么问题
- 我如何梳理用户体验
- 我做了哪些交互或界面决策
- 最后产出了什么可体验、可使用或高完成度结果

项目不按“好不好看”来选，优先选能证明 **产品体验 + 界面落地** 的内容。

## 我的差异化

- 工业设计背景：理解人与产品、人与系统的关系
- UI 落地能力：能把体验判断变成高完成度界面
- 产品落地意识：理解设计如何进入真实产品或原型
- 创意兴趣：作为加分项，不作为主定位

## 网站呈现方向

- 以专业稳定为主，降低过度个性化表达。
- 用产品逻辑和复杂界面能力建立可信度。
- 视觉创意可以出现，但只作为加分项。
- 页面不要让人误解为运营视觉、平面设计或营销设计作品集。

## 作品集文案用语原则

作品集文案的目的不是把每个项目套进统一句式，而是让招聘方快速理解：我为什么这样设计，以及我做出的关键判断是什么。

### 核心判断

- 文案应先帮助读者理解设计意图，再说明具体动作。
- 句式只用来检查目的和判断是否清楚，最终表达应根据项目内容自然组织。
- 好文案应像设计复盘，而不是项目包装话术。

### 写法倾向

- 少写“我做了什么”，多写“我为什么这样做”。
- 少写流程罗列，多写设计判断。
- 少用泛词，例如“优化体验”“提升效果”“打造闭环”。
- 多用具体对象，例如“功能演示”“用户路径”“模型选择”“操作反馈”“信息层级”。
- 文案要服务项目主线，不为了显得完整而解释所有细节。

### 检查问题

写完一段项目文案后，可以问：

- 这句话有没有说明设计目的？
- 这句话有没有体现我的关键判断？
- 读者是否能理解这个动作和用户体验之间的关系？
- 如果去掉形容词，剩下的信息是否仍然具体？
- 它听起来像真实复盘，还是像作品集模板句？

### 示例记录

模型编辑器新手指引段落中，原先的表达更偏执行记录：

> 我把新手指引拆成 6 类功能，并为每类功能匹配最能体现效果的模型特征。这样用户看到的不只是按钮怎么用，而是这个功能在什么模型场景下最容易被理解。

修改后更强调设计意图和判断：

> 为了让功能演示更清晰高效，我将新手指引拆成 6 类功能，并为每类功能选择最符合使用场景的模型。

这类修改的重点不是固定使用“为了……”句式，而是让文案先交代目的，再自然带出设计动作和取舍判断。
