# Website Visual Guidelines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从现有网站中提炼经用户确认的视觉规范，建立可视化参考和代码依据，同时保留已认可的页面效果。

**Architecture:** 先只读盘点，再区分全站规则、内容组件规则与项目例外。用户分批确认后制作独立样式展示页；展示与实际代码共用规则，先在 Selfly 反思区域验证，再按页面逐步推广。

**Tech Stack:** Next.js 16.2.10、React 19、CSS Modules、全局 CSS 变量、Markdown。

## 执行边界

- 本计划只安排工作，不授权立即进行全站重构、提交或推送。
- 内容文案、项目图片、网站导航与浏览器布局保持原样。
- 不把 Selfly 的橙色主题、长文行高和具体间距直接认定为全站标准。
- 每阶段留下可审阅产物；已确认的决定继续沿用，只确认新的或有冲突的规则。

## 文件职责

- `src/app/globals.css`：现有全站颜色、字号、基础排版与布局变量。
- `src/app/layout.tsx`：实际加载的字体及字重，盘点时核对，默认不更换字体。
- `src/components/CaseStudy.module.css`：共享案例布局与响应式导航。
- `src/app/[locale]/page.module.css`：首页现状样本。
- `src/app/[locale]/about/about.module.css`：关于页现状样本。
- `src/app/[locale]/projects/selfly/selfly0.module.css`：项目主题与长文阅读样本。
- `docs/visual-audit.md`：盘点结果、截图位置与差异清单。
- `docs/visual-guidelines.md`：用户确认后的规则及例外，包含使用情境与来源。
- `src/app/[locale]/style-guide/page.tsx` 与 `styleGuide.module.css`：确认方案后的独立展示页；不自动加入公开导航。

## 阶段 1：现状盘点与基线

- [x] 按 AGENTS.md 启动和复用应用内预览；检查工作区状态，记录基线提交。
- [x] 浏览首页、关于页、Selfly 及另一个案例；分别记录宽屏、窄屏的截图和 URL。
- [x] 读取全局样式、字体加载、共享案例样式与各样本 CSS；记录字号、字重、颜色、行高、间距、宽度、圆角和强调方式的来源。
- [x] 在 `docs/visual-audit.md` 分别标记现状、已确认偏好、待决差异。此阶段不改页面样式。

验收：每条判断有代码或截图依据，能说明哪些规则已经共用、哪些只是项目局部约定。

## 阶段 2：分层形成候选规则

- [x] 在 `docs/visual-guidelines.md` 分开记录全站基础、内容组件、项目主题及例外。
- [x] 每条规则写清用途、取值、响应式行为、来源和例外；不单纯把出现最多的数值认作标准。
- [x] 记录已确认的 Selfly 偏好：正文重点细下划线、放大观点不画线、强调字重 500、橙色分节标题、浅暖色区域和四角圆角、同组内容紧凑且章节留白明确。
- [x] 核对字体：当前 Geist 和 Noto Sans SC 加载 400/500，避免无依据地使用其他字重；保留已有装饰字体的限定用途。

验收：候选规范可以解释视觉取舍，不混淆全站规则与 Selfly 主题。

## 阶段 3：分批确认

- [ ] 先确认字体、文字层级与颜色，再确认间距、宽度、行高和圆角，最后确认强调、列表及提示区域。
- [ ] 每次只展示一个规则组，提供现状与建议的实际视觉对照。
- [ ] 将用户决定回写文档；不改变尚未确认的取值，也不再次询问已确认事项。

验收：关键规则具有明确决定，冲突的旧样式有保留或迁移理由。

## 阶段 4：制作样式展示页

- [ ] 实施前读取 `node_modules/next/dist/docs/` 中页面、样式和路由的相关指南。
- [ ] 按已确认规范落实展示页方案：标题、段落、重点文字、编号列表、提示区域、图片说明；示例包含真实中文与英文，并覆盖短文本、换行和长内容。
- [ ] 展示页复用现有变量与共享样式；确需提取组件时先明确作用范围，避免建立另一套独立样式。
- [ ] 通过直接本地 URL 审阅，不自动修改网站导航或增加配图。

验收：用户能直接比较规则的视觉效果，展示页与实际代码使用同一来源。

## 阶段 5：小范围试用

- [ ] 仅选择已反复确认的 Selfly 项目反思作首个试点，逐条映射已确认规则。
- [ ] 对照基线核对文案、标题、列表内容和顺序完全一致；只允许已确认的视觉差异。
- [ ] 在宽屏、768px 左右及 390px 左右检查换行、溢出、行长、间距和重点层次；恢复临时浏览器视口设置。
- [ ] 用户确认试点后，再决定推广页面及顺序，不一次替换全站样式。

验收：规则在真实长文中成立，且首页和其他项目没有意外变化。

## 阶段 6：验证与维护

- [ ] 新增页面或组件运行针对性 ESLint；运行 `git diff --check`。引入路由或共享结构时运行 `pnpm build`，如失败，区分变更问题和环境问题。
- [ ] 检查全站导航及样本页面的视觉回归；只有共享规则变化时才扩大检查范围。
- [ ] 在 `AGENTS.md` 中补充规范文档入口与维护原则，不覆盖已有要求：优先复用规则，新增例外必须记录用途和来源。
- [ ] 每个阶段独立保留差异与验证记录；用户要求时提交，推送按用户指令执行。

完成标准：规则文档、展示页与试点实现一致；明确项目例外；后续修改可以查到依据，而不必重新猜测字重、间距和圆角。

## 2026-11-15 范围更新

用户将后续工作调整为：对有广泛复用证据的现有样式直接收录，不再逐项确认。正式规范与候选讨论分开，页面采用 Geist 式表格，不展示确认标签或来源页面链接。此次执行及验证见 [现有规则整理](2026-11-15-established-visual-rules.md)。原计划中的全站迁移、Selfly 试点及AGENTS维护入口不随本次文档整理自动实施。
